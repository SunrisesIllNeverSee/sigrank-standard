# OEP-0001: Protocol Name and Versioning

**Status:** Draft
**Type:** Process
**Created:** 2026-08-28
**Author:** DREP1

## Summary

Proposes "OTEP" (Operator Token Efficiency Protocol) as the neutral protocol name, replacing the product-associated "SigRank Standard" in normative documents. Establishes the version string format and legacy alias policy.

## Motivation

The current specification is named "SigRank Standard," which is a product name. For vendor-neutral adoption, the protocol needs a name that is not associated with any single product. The "ASCII moment for AI measurement" positioning is effective for marketing but should not be the formal name.

## Specification

1. The protocol name is **OTEP** (Operator Token Efficiency Protocol).
2. The spec version string format is `otep/<major>.<minor>-<status>`.
3. The legacy version string `sigrank/0.1-draft` MUST be accepted as a backward-compatible alias for `otep/0.1-draft`.
4. The metric spec version format is `otep-metrics/<major>.<minor>-<status>`.
5. The conformance report version format is `otep-conformance/<major>.<minor>-<status>`.
6. "OTEP" should be used in all normative documents. "SigRank Standard" may be used in product documentation as a legacy reference.

## Rationale

- "Operator" centers the human, not the tool or model
- "Token Efficiency" describes what is measured without overclaiming
- "Protocol" signals interoperability
- Pronounceable as "oh-tep"
- No trademark conflicts identified in preliminary search (requires formal clearance)

## Backward Compatibility

The legacy alias `sigrank/0.1-draft` is accepted by all consumers. No existing implementation breaks.

## Conformance Impact

Conformance claims transition from "SigRank Compatible" to "OTEP Conformant." Both labels are valid during the transition period.
